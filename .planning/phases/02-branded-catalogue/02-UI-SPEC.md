# Phase 02 - UI Design Contract

> Visual and interaction contract for the Branded Catalogue phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Visual target: `docs/refs/misc-mockup.png` (All Items, filters, footer, mobile menu, style guide) and `docs/refs/just-dropped.png` (header, nav chevrons, card). Locked decisions come from `02-CONTEXT.md` (D-01 to D-24) and are cited as D-xx.
> Note: the branding PDF could not be rendered in this environment (no poppler). Palette and fonts were taken from `.planning/PROJECT.md`, which transcribes the PDF, and checked against the two mockup PNGs.

## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values (all multiples of 4). Tailwind's default 4px unit is kept, so `p-4` = 16px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon to label gap, badge padding-y |
| sm | 8px | Gap between chips, checkbox to label, card text rows |
| md | 16px | Grid gap on phones, card text block top margin, filter row padding, page gutter on phones |
| lg | 24px | Grid gap from 640px up, page gutter from 640px up, gap between filter groups |
| xl | 32px | Gap between sidebar and grid, footer column gap |
| 2xl | 48px | Footer padding-y, space between toolbar and grid on desktop |
| 3xl | 64px | Space above the footer, empty-state vertical padding |

Layout constants (also multiples of 4):

| Name | Value |
|------|-------|
| Container max width | 1280px, centred, gutter 16px (below 640px) or 24px (640px and up) |
| Header height | 64px on phones, 80px from 1024px |
| Header search bar row | 56px |
| Filter sidebar width | 256px (from 1024px) |
| Filter drawer width | `min(100vw - 48px, 384px)` |
| All Items banner height | 160px on phones, 224px from 768px |
| Card image frame | aspect ratio 4:5 (see Cards) |

Exceptions:
- Touch targets are 44px (a multiple of 4): header icon buttons, hamburger, chips' remove target, pager links, colour swatches (24px visible circle, 44px hit area), filter checkbox rows on phones (`min-h-11`). From 1024px, checkbox rows may drop to 32px.
- Hairlines are 1px borders (not a spacing step).

## Typography

Four sizes, two weights. Weight 400 is Montserrat only. Weight 700 is Bodoni Moda only (the only Bodoni file shipped; never synthesise bold on Montserrat). `SHELL-01` mentions Montserrat 500: it is intentionally NOT used, so the contract stays at two weights. Hierarchy comes from size, case and letter spacing instead. The variable font still allows 500 later with no extra file.

| Role | Size | Weight | Line Height | Face and treatment |
|------|------|--------|-------------|--------------------|
| Label | 12px | 400 | 1.5 | Montserrat, UPPERCASE, letter-spacing 0.16em (nav links, filter group headings, card brand, "NEW" badge, result count, sort, footer column headings, "Show more"). Also the sentence-case "Colour / Size" line (spacing 0, Olive) |
| Body | 16px | 400 | 1.5 | Montserrat, sentence case (filter option labels, price, chips, empty-state body, footer links and contact lines) |
| Heading | 24px | 700 | 1.2 | Bodoni Moda, section headings, drawer and menu titles, empty-state heading |
| Display | 40px | 700 | 1.2 | Bodoni Moda, "All Items" banner title. 32px is NOT allowed: on phones the banner title stays 40px (fits "All Items" in 343px) |

Card title: Bodoni Moda 700 at 16px, line-height 1.2, `line-clamp-2`. This is the one place the Body size takes the heading face; it is a size already declared, not a fifth size.

Buttons: Label role (12px caps, 0.16em), min-height 44px.

Prices: Body role, Montserrat 400, `tabular-nums`.

Rules: no italics anywhere (no Bodoni italic file is shipped). Never set Montserrat bolder than 400. Placeholder and disabled text may use Olive at full opacity (never below 4.5:1).

## Color

Tokens in `src/shop/theme.css` as Tailwind `@theme` colours: `--color-forest`, `--color-olive`, `--color-stone`, `--color-sand`, `--color-ivory`. Values are Blacktail Archive's (from `.planning/PROJECT.md`, matched against the style guide in `misc-mockup.png`). A different shop replaces this file.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Ivory `#E8E5DD` | Page background, header, filter sidebar, drawer and menu panels, footer, card text area |
| Secondary (30%) | Sand `#CBB89E` (and Sand at 40% opacity), Stone `#A69D8F`, Olive `#4A5A46` | Sand 40%: photo placeholder behind a loading card image, removable chip fill, disabled newsletter controls, hover fill of dropdown rows. Stone: 1px hairlines and input borders, swatch rim, unchecked checkbox border at 60% (never for text). Olive: secondary text ("Colour / Size", result count, helper text, placeholder) and link hover |
| Accent (10%) | Forest `#1F2A1F` | Listed below |
| Destructive | none | No destructive action exists in this phase (clearing filters only resets the URL) |

Text colour ("ink") is Forest on Ivory (about 11.9:1) and Ivory on Forest. Olive on Ivory is about 5.9:1, so it passes for body text. Stone on Ivory is about 2.3:1: Stone is for lines and decoration only, never for text or a meaningful icon.

Accent reserved for (Forest as a FILL or emphasis, in addition to its role as text colour):
1. The All Items banner background (behind the photo overlay) and the footer's top rule
2. The "Apply filters" button fill in the mobile drawer
3. The checked state of a filter checkbox (filled square with Ivory check)
4. The price and measurement slider's selected range and both thumbs
5. The ring around a selected colour swatch
6. The current page number in the pager (filled square, Ivory number)
7. The 2px keyboard focus ring (offset 2px, on every interactive element)
8. The "NEW" badge text and border (Ivory background)

Not accent: chips (Sand), links, icons, headings, dropdown panels, hover states.

Overlays: the drawer and mobile-menu backdrop is Forest at 50% opacity. The banner photo has a Forest overlay gradient (Forest 70% to 20%, left to right) so the Ivory title always has contrast of at least 4.5:1.

Banner placeholder: until the lifestyle photo arrives, the banner is solid Forest with no image. The image path comes from shop config (`src/shop/config.ts`, a `public/images/...` slot, `null` means placeholder).

## Layout and Interaction Contract

Every state lives in the URL (CAT-06). Param names equal the API's: repeated `type`, `brand`, `size`, `colour`, `era`, `condition`, `department`, `material`; `minPrice` and `maxPrice` (cents); `minPitToPitMm`, `maxPitToPitMm`, `minLengthMm`, `maxLengthMm`; `q`; `sort` (`newest`, `price_asc`, `price_desc`); `page`. Unknown params and values not in `/filters` are dropped before the API call. Any change except `page` resets to page 1 (CAT-07). A page past the last page redirects (307) to the last page. `newest` and page 1 are omitted from URLs.

### Header (SHELL-02, D-08, D-11, D-12, D-13)

- Sticky (`top-0`), Ivory, 1px Stone bottom rule, height 64px (phones) or 80px (from 1024px).
- Desktop: logo left (shop wordmark, height 40px, links to `/`); nav centred (Shop v, Brands v, Just Dropped, About, Contact; Label role, gap 32px; chevron 12px on Shop and Brands); right group: Search, Account, Wishlist, Bag `(0)` as 20px lucide icons (`Search`, `User`, `Heart`, `ShoppingBag`), each in a 44px target. Account, Wishlist and Bag are `<span aria-hidden>` (not links, not buttons, not focusable). Only Search is interactive.
- Phone: hamburger (`Menu`) left, logo centred (height 32px), Search and Bag icon right. Account and Wishlist appear only inside the menu.
- Nav links show the current route with a 1px Forest underline (offset 8px). Links point at real routes even when they 404 until Phase 3 and 4 (D-11).
- Search (D-13): the Search control is a disclosure (`<details>`/`<summary>` or a button with `aria-expanded`) that reveals a 56px bar under the header: a GET `<form action="/shop">` with one `name="q"` input (16px so iOS does not zoom), a submit icon button and a close button. It works without JS if built on `<details>`. Esc and the close button close it and return focus to the toggle. On `/shop` with `q` set, the input is prefilled. Submitting carries only `q` (a new search drops other filters).
- Dropdowns (D-12): one `NavDropdown` component for Shop and Brands. Disclosure pattern: a button with `aria-expanded` and `aria-controls`, a panel of links. Opens on click, Enter or Space; also on hover from 1024px (150ms open delay). Closes on Esc (focus returns to the button), outside click, route change, or focus leaving the panel. Panel: Ivory, 1px Stone border, padding 16px, min-width 224px. Brands panel is 2 columns, `max-height: 70vh`, scrolls inside. Rows min-height 44px on touch, 32px from 1024px; hover fill Sand 40%. Labels come from the label maps. Both lists are fetched with `/filters` through the tagged client, once per request, shared with the filter panel.
- Phase 3 may repoint the Brands rows to `/brands/[slug]`; the component takes `{ label, href }` pairs so nothing else changes.

### Mobile menu (SHELL-04)

- A `<dialog>` modal (use the Vintage `useModalDialog` pattern: focus trap, Esc, backdrop) that fills the screen height and slides in from the left, width 100vw below 480px, 384px above. Title row: logo and a `X` close button.
- Rows (Label role, 56px high, a `ChevronRight` at the end, 1px Stone rule between): Shop, Brands, Just Dropped, About, Contact. Shop and Brands expand in place as an accordion (button with `aria-expanded`, chevron rotates) listing the same links as the dropdown. A link row closes the menu.
- Bottom group (decorative, `aria-hidden`, non-interactive): Account, Wishlist, Bag (0), each with its icon.
- Body scroll is locked while open. No horizontal scroll at 320px.

### All Items page (`/shop`)

- Order top to bottom: banner (Display title, left, inside the container), toolbar, active chips, grid, pager. Sidebar sits left of toolbar and grid from 1024px.
- Toolbar: left, result count (Label role, Olive); right, `Sort by:` plus a styled native `<select>` (appearance none, `ChevronDown` icon, min-height 44px, Label role). Native select keeps it accessible and working without JS; changing it applies instantly. On phones the toolbar is one row: `Filter` button (`SlidersHorizontal` icon, opens the drawer) on the left and the sort select on the right, both 44px high, with a 1px Stone border; the count moves to its own line above the grid.
- Active chips: a wrapping row (gap 8px) of removable chips and a trailing `Clear all` text link (only when at least one chip exists). A chip is an `<a>` to the same URL minus that value (works without JS), min-height 40px, Sand fill, Forest text, `X` icon 16px at the end, `aria-label` "Remove filter: {label}". One chip per selected value. Chips scroll horizontally on phones only if they exceed three rows; otherwise wrap.
- Grid: 2 columns below 640px (gap 16px), 3 columns from 640px (gap 24px); the sidebar appears at 1024px and the grid stays at 3 columns. 24 cards per page. The `data-as-of` attribute from Phase 1 stays on the grid's section.
- Pager (numbered, CAT-07): `ChevronLeft`, page links, `ChevronRight`. Show first, last, current and one neighbour each side, with `...` between gaps. Links are 44px squares (Body role); the current page is a Forest filled square with an Ivory number; other pages are bare numbers with a 1px Stone border on hover. Hidden when there is one page. Following a page link scrolls to the top of the toolbar.
- Loading: navigation from a filter change keeps the old grid at 60% opacity with `aria-busy="true"` (use `useTransition`). A `loading.tsx` for `/shop` shows 8 skeleton cards (Sand 40% frame at 4:5, two text bars; no animation if `prefers-reduced-motion`).

### Filter panel (CAT-02, 03, 06, 08; D-14 to D-20)

- One `FilterPanel` client component wrapped around a GET `<form action="/shop">` used in two places: the sidebar (desktop) and the drawer (phones). Group order: Brand, Category, Size, Colour, Price, Era, Condition, Department, Material, Pit to pit, Length. Groups with no values in `/filters` are not rendered. Pit to pit and Length are hidden when their `/filters` range is `null` (D-16).
- Each group is a `<details>` with a Label-role `<summary>` heading and a `Plus`/`Minus` indicator. The first five (Brand to Price) are open by default; the rest are closed unless one of their values is selected. Groups are separated by 24px and a 1px Stone rule.
- Checkbox rows (Brand, Category, Size, Era, Condition, Department, Material): native `<input type="checkbox">` visually restyled (16px square, 1px Forest border; checked = Forest fill with an Ivory `Check` icon), label in Body role. No counts (D-17). Show the first 8 values in `/filters` order, then a `Show more` button (Label role, `aria-expanded`) expands the rest in place; selected values always show even when beyond 8. Size values keep API order (most common first), no custom sort.
- Colour (D-15): a wrapping row of 24px round swatches, gap 12px, each a checkbox in a 44px target with the colour name as its accessible label and `title`. Hex comes from the shop's colour map. Unselected: 1px Stone rim. Selected: 2px Forest ring with a 2px Ivory gap. An unknown colour renders a neutral Sand swatch followed by its name in Label role (sentence case), so it is never anonymous. Light swatches always keep the Stone rim.
- Range sliders (Price, Pit to pit, Length; D-16): two overlaid native `<input type="range">` (min and max, so keyboard and screen readers work), 4px Stone track, Forest selected range, 20px Forest round thumbs with a 44px hit area. Bounds are the `/filters` min and max; steps are €1 for price and 1cm for measurements. Above the track, a read-out in Body role: `€20 to €80`, `50 to 60 cm`. The handles cannot cross. The URL carries cents (price) and mm (measurements). A slider at its full bounds adds no param.
- Desktop apply (D-14): changes apply instantly: checkbox and swatch toggles after a 250ms debounce, sliders on release (the `change` event, not `input`). The URL is updated with `router.push(..., { scroll: false })` so Back undoes a change. With JS off, a visible "Apply filters" button (in a `<noscript>`-safe form) submits the GET form.
- Phone drawer (CAT-08): a `<dialog>` that slides in from the left (width in Spacing), titled "Filter", with a close `X`. The groups scroll; a sticky footer holds a full-width Forest "Apply filters" button and a "Clear all" text button above it or beside it (stacked, 44px each). Changes inside the drawer are held in the form and only applied by Apply; closing with X, Esc or the backdrop discards them. Applying closes the drawer and moves focus to the result count.
- The sidebar scrolls with the page (not sticky) so it never traps a short viewport.

### Item card (CAT-01, CAT-10, D-21 to D-24)

- The whole card is one `<a href="/items/{code}">` (no nested interactive elements). Hover: image scales to 102% over 200ms (disabled under `prefers-reduced-motion`). Focus: the 2px Forest ring wraps the card.
- Image frame: `aspect-ratio: 4 / 5`, Sand 40% fill, `object-cover`, image is `thumbUrl` through `next/image` with the API's `width` and `height` passed, `unoptimized` (project setting). The frame reserves space, so nothing shifts. The first 4 cards use `priority`; the rest lazy-load. An item with no photo shows the empty Sand frame (does not occur with the API's rules, but never crashes).
- Overlays on the photo: "NEW" badge top-left at 8px inset (Ivory fill, Forest text and 1px Forest border, 4px 8px padding, Label role), shown when `publishedAt` is within the config's New-badge days (7, D-21). A heart top-right at 8px inset: lucide `Heart`, 20px, Ivory stroke on a Forest 40% circle (32px), `aria-hidden`, not focusable, not a button (D-24).
- Text block (16px above): brand (Label role, caps, omitted when null), title (Bodoni 700 16px, 2 lines max), "Colour / Size" (Label role in sentence case, Olive; skips a missing part and the slash, omitted if both missing), price (Body, formatted `€120` or `€119.50`, D-22). Rows 4px apart.
- Money: one formatter from integer cents, `Intl.NumberFormat('en-IE', { style: 'currency', currency })` with `minimumFractionDigits: 0` and `maximumFractionDigits: 2`, but cents shown when the amount has them (so `€119.50`, never `€119.5` or `€120.00`). Used for cards, chips and the slider.

### Footer (SHELL-03, D-05 to D-08)

- Ivory with a 1px Forest top rule and 48px vertical padding. Desktop: four columns (gap 32px): logo plus the five social icons; Explore (Shop, Brands, Just Dropped, About, Contact; same labels as the header); Find us (email, Vinted, eBay); Newsletter. Phones: single column in the same order; the Explore list may sit beside Find us in two columns from 480px.
- Social icons (D-07): Instagram, TikTok, Pinterest, Spotify, 24px glyphs in 44px targets. An icon with a URL in config is an `<a>` with an `aria-label` (the network name) opening in a new tab; an icon without a URL is a `<span aria-hidden>` (decorative, no link). Instagram is `https://www.instagram.com/blacktailarchive` from config.
- Vinted and eBay links come from config (placeholder values until supplied, D-05); render them as given.
- Newsletter (D-06) is a visual mock only: a plain `<div>` (not a `<form>`, never submits, no handler) holding a disabled text input (visible placeholder "Email", hidden label) and a disabled "Subscribe" button with an `ArrowRight` icon, both Sand 40% fill with Olive text. The visible note "Newsletter signup is coming soon." is linked to the input by `aria-describedby`. No provider, no network call.
- Legal line below a 1px Stone rule: Label role, Olive.

### Motion and accessibility

- Transitions 150 to 200ms, `ease-out`; all motion off under `prefers-reduced-motion: reduce`.
- All text meets 4.5:1. Every interactive element has a visible 2px Forest focus ring, offset 2px. Focus order follows visual order. The result count is `role="status"` (`aria-live="polite"`) so instant filter changes are announced.
- One `<h1>` per page (the banner title). The sidebar is `<aside aria-label="Filter">`. The grid is a `<ul>` of `<li>` cards.
- External links use `rel="noopener noreferrer"`.
- No horizontal scroll at 320px: grid, chips, pager (wraps) and drawer must all fit. Test at 320px, 375px, 768px, 1024px and 1280px.
