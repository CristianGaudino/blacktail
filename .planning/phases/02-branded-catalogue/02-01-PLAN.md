## Phase Goal

**As a** shopper, **I want to** browse, filter, search, sort and page through the shop's in-stock pieces in the Blacktail Archive look on desktop and phone, **so that** I can quickly find pieces in my size, brand and budget.

<objective>
Move the stock page to `/shop` and make every catalogue choice a URL that reaches How many cleaned. After this plan a shopper (or a shared link) can open `/shop?brand=...&colour=...&q=...&sort=...&minPrice=...` and see exactly that selection from the API, with junk in the URL dropped instead of breaking the page. `/` redirects to `/shop` (D-10).

Purpose: the URL query layer is the contract every later plan builds on (chips, sort, pager, filter panel, canonical URLs). Proving it end to end first, through the existing cache contract and the Phase 1 freshness proof, keeps the riskiest wiring (cache keys, redirect, proofs that assumed `/`) out of the UI work.
Output: `/shop` page, `src/lib/params.ts`, `getFilters` + `getItemsPage`, a 30-item mock with `/filters`, and `prove-freshness.mjs` on `/shop`.

Task 1 is `type="tracer"` on purpose (TRACER_MODE): one brand filter and the page number go from the URL through `/filters` to the API and back to the list. Task 2 fills in every other param in the same functions (no architectural change).

Scope rationale for Task 1 (12 files): seven of them are edits of five lines or fewer (next.config redirect, routes, config, copy, definitions, schemas, page delete). Splitting would leave a task with no end-to-end path to prove.
</objective>
