## Phase Goal

**As a** shopper, **I want to** browse, filter, search, sort and page through the shop's in-stock pieces in the Blacktail Archive look on desktop and phone, **so that** I can quickly find pieces in my size, brand and budget.

<objective>
Draw the template seam. After this plan every shop-specific value lives in `src/shop/`, every generic word the phase shows lives in `COPY`, code labels fall back safely, and a test fails if a shop value leaks anywhere else.

Purpose: Plans 05 to 09 import SHOP and COPY keys by name. Writing the whole phase's generic COPY here (from the UI-SPEC copywriting contract) is deliberate: Plans 05 and 06 run in parallel in wave 4 and Plans 07 and 08 in wave 5, and they would otherwise all edit src/lib/copy.ts.
Output: `src/shop/config.ts` (full SHOP), `src/shop/colours.ts`, the COPY deck with code-label maps, `label()`, the shop-string guard.

Runs in wave 3 beside Plan 04 (money, dates and paging rules). The two share no file and run unit tests only, so neither starts a server or takes a port.
</objective>

## TMPL-01 scope in this phase (recorded re-scope, owner-visible)

TMPL-01 lists the per-shop items: name, copy, contact, platform links, theme tokens, fonts, images, default brand order, category tiles. Phase 2 delivers name, contact, platform links, socials, the colour map, New-badge days and the banner image slot (this plan), shop wording kept out of COPY (this plan), theme tokens and fonts (Plan 02), the logo (Plan 06), and the guard that keeps all of them inside `src/shop/` (this plan). Two items have no consumer in this phase and are not added here, so no unused config ships:

- **Default brand order:** only BRAND-02's home brand strip (Phase 4) orders brands by it. The header's Brands dropdown keeps the /filters order (most common first) per D-12 and Plan 06's ordering truth, so it must not read a configured brand order.
- **Category tiles:** HOME-01 and HOME-03 (Phase 4) render them.

Both land as fields in `src/shop/config.ts` with those Phase 4 requirements, inside the same folder and behind the same guard. REQUIREMENTS.md keeps TMPL-01 mapped to Phase 2 and its TMPL-01 line carries a note (added at planning time, not by this plan) that these two items land in Phase 4 with BRAND-02, HOME-01 and HOME-03; the phase PR body (Plan 10) lists this split for the owner, and the Phase 2 verifier should check TMPL-01 for every item except these two.
