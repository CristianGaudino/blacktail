## Typography

Existing scale, no additions. Exactly four sizes and two weights are used on this page:

| Role | Size | Weight | Line Height | Used for in this phase |
|------|------|--------|-------------|------------------------|
| Body | 16px (`text-base`) | 400 | 1.5 | Sold message, "This piece is listed on ..." line |

## Layout and Component Contract

### 1. Sold badge on the cover photo (D-01)

- Component: an optional `soldLabel?: string` prop on `ItemGallery` (a plain string, so the RSC payload stays free of item details). Page passes `COPY.item.sold` only when the item is sold.
- Position: `absolute left-2 top-2 z-10` (8px from the top-left corner of the photo frame). Parent: the plain column wrapper `<div>` that contains the track, which gains `relative`. NOT inside the scrolling snap track (it would scroll away with slide 1) and NOT over the thumbnail rail.
- Style: `pointer-events-none border border-forest bg-forest px-2 py-1 text-label uppercase text-ivory`. Size is content-driven (about 24px tall). Small, not a full overlay, as chosen.
- `pointer-events-none` keeps the photo click and the lightbox working under the badge.
- `aria-hidden="true"`: the "Sold on <date>" line in the right column carries the meaning for screen readers, so Sold is not read twice.
- Does not carry over into the lightbox (the viewer shows the photo only).
- Zero photos: the existing `aspect-[4/5] bg-sand/40` placeholder shows and the badge still sits in its top-left corner.
- The photo is NOT dimmed, greyed or filtered. Sold pieces keep full-colour photos.

### 2. Right column, sold state (D-01, D-02, D-03)

Order top to bottom, using the existing wrappers:

1. Brand label (unchanged, links to the brand page when `slug` resolves).
2. `h1` title (unchanged).
3. Sold line, where the price was: `<p className="mt-4 font-heading text-heading">` with `COPY.item.soldOn(formatDay(soldAt))`, e.g. "Sold on 3 November 2026". When `soldAt` is null render `COPY.item.sold` ("Sold") alone. No relative dates, no price, no strikethrough price, no "was". `priceCents` is not rendered anywhere in the markup (D-02), including `aria` text.
4. `SoldNotice` in place of `WhereToBuy`, wrapped in `<div className="mt-6">`.
5. `ItemDetails` in `<div className="mt-8">`, unchanged.
6. No "More from this brand" row (page skips the read).

### 3. SoldNotice (new component, D-03)

- Container: `<section className="bg-sand/40 p-6">`, the same panel as `WhereToBuy`, so the right column keeps one visual language.
- Message: `<p className="text-base">{COPY.item.soldMessage}</p>`.
- Actions: `<div className="mt-4 flex flex-col gap-2 min-[480px]:flex-row">` containing, in this order:
  1. `ButtonLink variant="primary" href={ROUTES.shop}` with `COPY.common.shopAll` ("Shop all items"). Internal link, no icon.
  2. `ButtonLink variant="secondary" href={ROUTES.justDropped}` with `COPY.item.newestDrops` ("See the newest drops"). Internal link, no icon.
- No price call to action, no external link, no platform names, no wishlist or "notify me" control.
- Heading: none inside the panel (the page `h1` is the title and the sold line states the status; an extra heading would add a third h-level for one sentence).

### 4. WhereToBuy with per-item listings (D-08..D-11)

Takes `listings` (already filtered to https by the schema). Two renderings:

**A. One or more listings** (LINK-01)
- Panel: `<section className="bg-sand/40 p-6">`, unchanged.
- Intro: `<p className="text-base">{COPY.item.listedOn(names)}</p>` where `names` is `Intl.ListFormat(SHOP.locale, { type: 'conjunction' })` over the display names of THIS item's listings, de-duplicated (so two listings that resolve to the same name read once), e.g. "This piece is listed on eBay and Vinted".
- No second help line in this mode (`whereToBuyHelp` talks about the shop profile and would be wrong here).
- Buttons: `<div className="mt-4 flex flex-col gap-2 min-[480px]:flex-row">`, one `ButtonLink external variant="secondary"` per listing, in API order (no sorting), each: label `COPY.item.buyOn(name)` ("Buy on eBay"), then `<span className="sr-only">{COPY.common.opensInNewTab}</span>`, then `<ExternalLink size={16} aria-hidden />`. Full width stacked below 480px comes from the column flex; from 480px a row. With many listings the row wraps (`flex-wrap` added to the row class so 3 or more buttons do not overflow at 480 to 640px).
- Name resolution: case-insensitive match of the listing platform code to `SHOP.platforms[].name`; otherwise the URL hostname without a leading `www.`. Never show the raw code or the raw URL as text.

**B. No listings (empty after filtering)** (LINK-02): exactly today's profile panel, unchanged: `listedOn` over `SHOP.platforms` names, the `whereToBuyHelp` line, one `visitOn(name)` button per platform profile. Returns `null` when `SHOP.platforms` is also empty.

### 5. Interaction states

| Element | Default | Hover | Focus-visible | Active / disabled |
|---------|---------|-------|---------------|-------------------|
| Listing / profile buttons (secondary) | forest border, forest text | no change beyond the existing button class (none defined for secondary; do not add one in this phase) | global `:focus-visible` outline: 2px forest, 4px offset | none, links never disabled |
| Primary / secondary buttons in SoldNotice | as above | as above | as above | none |
| Sold badge | static | none | not focusable | not interactive |
| Photo under the badge | zoom-in cursor (existing) | existing | existing | existing |

No new animation, transition or motion. Nothing in this phase needs a `prefers-reduced-motion` branch.

### 6. Responsive

| Viewport | Behaviour |
|----------|-----------|
| below 480px | Gallery full-bleed, badge 8px inside the corner; all buttons in both panels stacked, full width of the column |
| 480px to 1023px | Buttons in a wrapping row; single page column |
| 1024px and up | Two-column grid; badge on the cover; right column carries the sold line, the panel and the details |

## Copywriting Contract

All strings live in `COPY` (`src/lib/copy.ts`); no em dashes (`copy.test.ts` enforces). Platform names come from `SHOP.platforms`, never from a component.

| Element | Copy |
|---------|------|
| Sold badge | `COPY.item.sold` = "Sold" |
| Sold line (date known) | `COPY.item.soldOn(date)` = "Sold on 3 November 2026" (long date in `SHOP.locale`, `dateStyle: 'long'`, `timeZone: 'UTC'` because `soldAt` is a day key) |
| Sold line (date null) | `COPY.item.sold` = "Sold" |
| Sold message | `COPY.item.soldMessage` = "This piece has been sold. Have a look at what else we have." |
| Primary CTA (sold page) | "Shop all items" (existing `COPY.common.shopAll`) |
| Secondary CTA (sold page) | `COPY.item.newestDrops` = "See the newest drops" |
| Listing button | `COPY.item.buyOn(name)` = "Buy on eBay" (only for per-item listings) |
| Listing intro | `COPY.item.listedOn(names)` = "This piece is listed on eBay and Vinted" (existing key, names from the item's own listings) |
| Profile fallback button | `COPY.item.visitOn(name)` = "Visit us on Vinted" (kept; also used by `ContactPanel`) |
| Meta description prefix | `COPY.seo.sold` = "Sold." then a space, then the existing description |
| Neutral 404 title (D-07) | `COPY.gone.title` = "This piece is no longer available" |
| Neutral 404 body (D-07) | `COPY.gone.body` = "It may have been removed. Here are our newest pieces." |
| Empty state | not applicable on this page; the 404 keeps `COPY.stock.empty` for an empty drops list |
| Error state | unchanged `COPY.status` copy via `error.tsx` ("Something went wrong ... Please try again in a moment."), shown for 429/500/parse failures; never a fake Sold or 404 (D-06) |
| Destructive confirmation | none; this phase has no destructive action |

Tone: short, calm, no urgency, no exclamation marks, no "hurry", no "gone forever". The sold page is informative, not a sales push.

## UI Considerations

Applicable state considerations resolved: 11 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | listings (empty or all-invalid) | ✅ covered | An item with no usable listings renders the profile-link panel exactly as in v1.0; with no platforms in config either, the block is omitted |
| empty | photos on a sold piece | ✅ covered | Zero photos renders the existing placeholder box with the Sold badge in its corner; JSON-LD omits `image` and the default OG image is used |
| partial | `soldAt` null | ✅ covered | The line reads "Sold" with no date; never "Sold on null" or "Invalid Date" |
| partial | `priceCents` null (sold, never priced) | ✅ covered | No price is rendered on a sold page in any case; JSON-LD omits `price` when null; no `formatMoney(null)` call |
| partial | empty `brand` ("" not null) | ✅ covered | Brand label hidden, title alone (existing guard), badge and sold line unaffected |
| zero-one-many | one listing | ✅ covered | One "Buy on <Platform>" button and an intro naming that one platform |
| zero-one-many | many listings (3+) | ✅ covered | Buttons wrap in the row and keep API order; intro uses a conjunction list (de-duplicated) |
| partial | unknown platform code | ✅ covered | Button label falls back to the URL hostname without `www.` |
| long-text | long title / long brand on a sold page | ✅ covered | Title keeps `break-words`; the sold line is short; no truncation introduced |
| error | API 404 vs 429/500 | ✅ covered | 404 or malformed code is the real 404 with newest drops; any other failure reaches `error.tsx` (D-06) |
| populated | in-stock page after the change | ✅ covered | Unchanged except per-item "Buy on" buttons; no badge, price shown, More from this brand shown |
| overflow | button row at 480 to 640px with 3+ listings | 🧪 backstop | Row wraps via `flex-wrap`; visual check on a device or in the PR preview, no automated layout test |

## Assumptions and Decisions Recorded (no user questions were asked)

1. **Badge colour** inverse of the "New" badge (forest fill, ivory text), `aria-hidden`. Within the discretion CONTEXT.md grants.
2. **Sold line typography** reuses the price styling (Bodoni 24px) so the layout does not jump, minus `tabular-nums`.
3. **Newest drops link** is a secondary `ButtonLink` to `ROUTES.justDropped`, beside the primary Shop all items button (RESEARCH open question 2).
4. **`visitOn` stays** for the profile fallback and `ContactPanel`; `buyOn` is used only for per-item listing buttons (RESEARCH A2). Confirmed by the owner on 2026-11-06 (D-08 amended).
5. **No second help line** under the listing intro (the profile help sentence would be misleading for an exact listing).
6. **Listing buttons stay `variant="secondary"`** (D-10 keeps today's panel and style); there is no filled "Buy" button because checkout is out of scope and the listing is on another site.
7. **Platform name de-dup** in the intro sentence so "eBay and eBay" cannot appear if two listings resolve to one name.
8. **`flex-wrap`** added to the button row so many listings cannot overflow; the only change to the existing row class.
9. **Sold photos are not dimmed or desaturated**, so the badge and line alone signal the state.
10. **Badge is not repeated in the lightbox.**
