## Phase Goal

**As a** shopper, **I want** a sold piece's address to keep working as a clear Sold page, and a piece that is for sale to send me to its exact Vinted or eBay listing, **so that** shared links never dead-end and I land on the right listing.

<objective>
Ship per-item listing buttons as a vertical slice: the detail read now carries `listings` (https only), and the where-to-buy panel shows one "Buy on <Platform>" button per listing that opens that exact listing in a new tab. A piece with no usable listing keeps today's profile-link panel. The Sold page from Plan 01 is untouched (it never shows where-to-buy).

Purpose: LINK-01, LINK-02 and success criteria 4 and 5. The schema is the trust boundary: a listing URL becomes an `href`, so only https URLs may pass.
Output: listings on itemDetailSchema, `COPY.item.buyOn`, WhereToBuy taking the item's listings, the page wiring, MOCK-0003 with two listings, and the edge cases pinned by tests. The workerd proof is Plan 03.
</objective>

API facts (RESEARCH Pattern 1 and Pattern 5): `listings` is `{ platform, url }[]` on the detail read, platform a lowercase code (`vinted`, `ebay`, `depop`, ...), url https, ordered by platform code (ebay before vinted), and empty for a sold piece or a piece with none. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| How many API -> anchor href | A listing URL from the API becomes an `href` on the item page |
| Item page -> third-party listing site | The buttons open Vinted, eBay or another host in a new tab |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Tampering (XSS through a javascript: or data: href) | itemDetailSchema listings | high | mitigate | `z.url({ protocol: /^https$/ })` per entry; failing entries are dropped before any component; client.test.ts pins `javascript:alert(1)` and `http://` being dropped |
| T-05-07 | Spoofing (reverse tabnabbing) | WhereToBuy / ButtonLink external | low | mitigate | `ButtonLink external` always renders `target="_blank" rel="noopener noreferrer"`; ItemInfo.test.ts and the harness assert both on each listing anchor |
| T-05-08 | Spoofing (a listing pointing to an unexpected host) | WhereToBuy | low | accept | The URL comes from the shop's own How many account over the public API (already https-filtered there); an unknown platform is labelled with its real hostname, so the buyer sees where the button goes |
| T-05-09 | Information disclosure | WhereToBuy | low | mitigate | Only the display name and the href are rendered; the platform code and the URL are never printed as text (test asserts the URL appears once) |
| T-05-SC | Tampering | npm installs | high | accept | No package is installed or added |
</threat_model>
