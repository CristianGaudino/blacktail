## Phase Goal

**As a** shopper, **I want to** land on a home page that matches the Blacktail Archive mockup, see the latest drops and read the shop's story and contact details, **so that** I trust the shop and come back for new pieces.

<assumption_delta_decision>
- Signal: pluralization ("deploy the template for another shop", ROADMAP success criterion 5).
- Primary noun: the shop deploy (one repo copy, one Worker, one src/shop folder, one env per shop). It has been the identity since Phase 1 (STORE_SLUG env, the src/shop seam and the shop-string guard from Phase 2).
- Decision: no-change. A second shop is a second deploy, not a second tenant in one deploy, so nothing is promoted or added alongside.
- Invariant test: the existing shop-string guard keeps shop values in src/shop; this plan adds src/lib/onboarding.test.ts so the deploy guide cannot drift from the template.
</assumption_delta_decision>

<objective>
Prove the phase on Cloudflare's runtime, wire the one launch switch into the deploy, close the non-production hosts, write the second-shop onboarding doc, and hand the PR to the owner.

Purpose: SEO-03 on workerd and in production (D-16), TMPL-02 (D-19), and success criteria 4 and 5. OpenNext cannot build on Windows, so CI is the only place the Worker runs; the header is fixed at build, so the deploy must pass the flag to both the build and the Worker (RESEARCH Pitfall 1).
Output: ci.yml and deploy-workers.yml updates, wrangler.jsonc with workers.dev and preview URLs off, .env.example and README updates, docs/ONBOARDING.md with its drift test, the phase PR with green checks and the UAT comment.
</objective>
