# Phase 03 - UI Design Contract

> Visual and interaction contract for the Item and Brand Pages phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Visual target: the item page and Brands page tiles in `docs/refs/misc-mockup.png` (thumbnail column + large photo + info column; Brands banner + tile grid), card and header from `docs/refs/just-dropped.png`. Locked decisions come from `03-CONTEXT.md` (D-01 to D-16) and are cited as D-xx.

Layout constants (multiples of 4):

| Name | Value |
|------|-------|
| Item page columns (from 1024px) | `grid-cols-[minmax(0,7fr)_minmax(0,5fr)]`, gap 48px. Below 1024px a single column: gallery, then info |
| Thumbnail column | 80px wide, thumbnails 80 x 100 (4:5), gap 8px, 16px from the large photo, desktop only (from 1024px) |
| Large photo frame | Width of its column; aspect ratio taken from the COVER photo's API `width / height` and kept for every photo (see Gallery). No cover: 4:5 |
| Phone gallery | Edge to edge: the track bleeds through the page gutter (`-mx-4` below 640px, `-mx-6` from 640px to 1023px) |
| Details label column | 128px (the value column takes the rest) at every width, so it fits at 320px |
| Brand tile | Aspect ratio 3:2, padding 24px around the logo |
| Brand tile grid | 2 columns below 640px (gap 16px), 3 columns from 640px (gap 24px), 4 columns from 1024px |
| More from brand / Newest drops grid | 2 columns below 1024px (gap 16px, then 24px from 640px), 4 columns from 1024px (gap 24px) |
| Lightbox header | 64px high; photo area fills the rest of the viewport (`100dvh - 64px`) |

Exceptions:
- Touch targets stay 44px: thumbnails (80px wide, so already larger), lightbox arrows and close (44px), platform link buttons (`min-h-11`), the brand label link and "View all" link (`min-h-11` hit area through padding), brand tiles (3:2 tiles are always larger).
- Photo-position dots are 8px visible and are not interactive, so no 44px target applies to them.
- 1px hairlines and the 2px selected-thumbnail border and focus ring are strokes, not spacing steps (same rule as Phase 2).

## Color

Inherited: Dominant Ivory 60%, Secondary Sand / Stone / Olive 30%, Accent Forest 10%. No destructive colour (no destructive action in this phase).

| Role | Value | New usage in this phase |
|------|-------|-------------------------|
| Dominant (60%) | Ivory `#E8E5DD` | Item page, brand tiles, lightbox background |
| Secondary (30%) | Sand 40%, Stone, Olive | Sand 40%: photo frame behind every gallery image, where-to-buy panel fill, brand tile hover fill. Stone: 1px dl row rules, 1px brand tile border, inactive dots (decoration only). Olive: detail labels and section headings on Ivory only (never on the Sand panel) |
| Accent (10%) | Forest `#1F2A1F` | Listed below |

Accent reserved for (this phase, on top of the Phase 2 list):
1. The 2px border around the selected thumbnail (desktop)
2. The filled dot for the current photo (phone)
3. The Forest FILL of the one primary button on the gone-item page and on the generic not-found page ("Shop all items")
4. The Forest banner behind the Display title on `/brands` and `/brands/[slug]` (same banner as All Items)
5. The 2px keyboard focus ring (offset 4px) on every new interactive element

Not accent: platform link buttons (secondary: 1px Forest border, Forest text, no fill), the where-to-buy panel (Sand 40%), brand tiles, links, headings, the lightbox.

Contrast notes: Olive text is allowed only on Ivory (about 5.9:1). On the Sand 40% where-to-buy panel all text is Forest. Stone is never used for text.

Brand logos are shown exactly as supplied (Levi's is red, Reebok has grey; that is the brand's own colour and is exempt from the palette rule). Several supplied SVGs carry a white square background (Nike, Polo Ralph Lauren, The North Face, Timberland, Vans, Stussy). The logo `<img>` therefore uses `mix-blend-multiply`, so white disappears into the tile fill and dark marks stay dark. Never use `invert` or recolour a logo.

## Layout and Interaction Contract

### Item page (`/items/[code]`; ITEM-01 to ITEM-05, D-01 to D-08)

Primary focal point: the large photo (above the fold on every viewport). Secondary: the item title and price, then the where-to-buy panel. The details list stays visually quiet.

Order, phone: gallery (edge to edge), brand, title, price, where-to-buy panel, Details, Measurements, More from. Desktop (from 1024px): left column gallery, right column the same stack from brand down to Measurements, and More from spans the full width below. The right column is not sticky.

Page padding: 24px top (phone) / 48px (desktop), 64px above the footer. No breadcrumb, no heart, no "Add to bag", no size pills, no accordions ("Product details", "Shipping & returns", "Authenticity" in the mockup are intentionally left out: no checkout, no data for them).

#### Gallery (D-01 to D-04)

One component, one set of full-size images, used on every viewport:

- **Track.** A horizontal scroll-snap track (`overflow-x-auto`, `snap-x snap-mandatory`, each slide `w-full shrink-0 snap-center`, scrollbar hidden) shows one photo at a time. On phones the shopper swipes it. On desktop the same track is driven by the thumbnails (and trackpad swipe still works). No carousel library.
- **Frame and no layout shift.** The track's aspect ratio is the cover photo's `width / height` (set inline), 4:5 when there is no photo. Every slide fills that frame with Sand 40% behind and `object-contain`, so a different-shaped photo letterboxes on the Sand instead of resizing the page. Each `<Image>` still receives its own API `width` and `height`, `unoptimized`, source is the API `url` (D-04).
- **Loading.** The first photo uses `priority` (eager, `fetchPriority="high"`); all others `loading="lazy"`.
- **Thumbnails (desktop only, `hidden lg:block`).** A vertical column on the left, 80 x 100 each, source `thumbUrl`, lazy, `object-cover`, gap 8px. The column is exactly as tall as the large photo and scrolls inside itself (`overflow-y-auto`, scrollbar hidden) when there are more thumbnails than fit. Each is a `<button>` (`aria-label` "Show photo {n}", `aria-current="true"` when shown). Selected: 2px Forest border. Unselected: no border, 1px Stone border on hover. Clicking scrolls the track to that photo (smooth; instant under `prefers-reduced-motion`).
- **Dots (phone and tablet only, `lg:hidden`).** Centred under the photo, 8px circles, gap 8px, current one Forest fill, others Stone. `aria-hidden`, not interactive. When there are more than 10 photos the dots are replaced by the text `{n} / {total}` (Label, Olive) so the row never overflows 320px. A visually hidden `aria-live="polite"` line announces `Photo {n} of {total}`.
- **Current photo.** The current index follows the visible slide (IntersectionObserver on the track, threshold 0.6, or scrollend) and drives the thumbnails, dots and counter.
- **Semantics.** The track is `role="region"`, `aria-roledescription="carousel"`, `aria-label="Photos"`, `tabIndex={0}` (arrow keys scroll it natively). Each slide is `role="group"`, `aria-roledescription="slide"`, `aria-label="Photo {n} of {total}"`.
- **Open lightbox (D-03).** The photo inside each slide is a `<button>` with `cursor-zoom-in`, `aria-label` "Open photo {n} of {total} full size", opening the lightbox on that photo.
- **One photo.** No thumbnail column (the gallery is just the large photo), no dots, no arrows in the lightbox. **No photos** (the API should not allow it, but never crash): the Sand 40% 4:5 frame with no trigger.

#### Lightbox (D-03)

- A client `<dialog>` built on `useModalDialog` (focus trap, Esc, backdrop-click come from the hook and the browser). It is full viewport, not a Sheet: it does not slide in; it fades in over 150ms (none under reduced motion). Reuse the `Sheet`'s class conventions (`m-0 h-dvh max-h-dvh w-screen max-w-none bg-ivory p-0 outline-none`), but do not apply the `.sheet` slide animation.
- Header 64px with a 1px Stone bottom rule: counter on the left (Label, `aria-live="polite"`), close `IconButton` (`X`) on the right.
- Body: the current photo, `url`, `fill` with `object-contain`, `sizes="100vw"`, Sand 40% behind it, `unoptimized`. Only the current photo is mounted; previous/next are not preloaded.
- Arrows: `ChevronLeft` and `ChevronRight` in 44px circular buttons (Ivory fill, 1px Stone border, Forest icon), vertically centred, 16px from each edge. Hidden when there is one photo. They wrap around (last goes to first).
- Keyboard: Esc closes (hook), ArrowLeft and ArrowRight move. Focus lands on the dialog when it opens (hook) and returns to the photo button that opened it when it closes. Body scroll is locked (global `body:has(dialog[open])` rule already exists).
- On close the gallery track scrolls to the photo the lightbox ended on, so the page and the lightbox agree.

#### Info column

- **Brand** (Label, caps) is a link to `/brands/[slug]` (slug from the shared brand-slug helper, D-14); omitted when the item has no brand.
- **Title** `<h1>`, **price** below it with a 16px gap (price formatted by `formatMoney`, never raw cents).
- **Where-to-buy panel (D-07).** Sits right under the price (it takes the place of the mockup's "Add to bag"). Sand 40% fill, padding 24px, no border. Inside: the listed-on line (Body), the helper line (Label, sentence case), then one link button per `SHOP.platforms` entry: secondary variant (1px Forest border, no fill), full width stacked on phones, side by side from 480px (gap 8px), each with a trailing `ExternalLink` icon (16px). If `SHOP.platforms` is empty the whole panel is left out. The links go to the shop profiles, never to a per-item URL.
- **Details (D-05).** A `<dl>`: each row is `grid-cols-[128px_1fr]`, 8px padding-y, 1px Stone rule between rows (top rule on the first). Row order: Size, Colour, Era, Department, Condition, Material. A row whose value is null, empty or missing is left out entirely. Condition is always present. Material is read from the item's `details` object when it holds a text value (the planner confirms the key against the live API; if there is none the row is simply absent).
- **Measurements (D-06).** Same `<dl>` layout with the heading "Measurements". Rows: Pit to pit, Length. A row with a null value is omitted; the whole block (heading included) is omitted when both are null. Never show cost, notes or internal ids (CLAUDE.md privacy rule).

#### More from this brand (D-08)

- Full-width section below the two columns, 64px above. Header row: heading `More from {brand}` (Heading) on the left, "View all" link to `/brands/[slug]` on the right (Label, caps, vertical centre, 44px hit area).
- Body: the existing `ItemGrid`/`ItemCard`, 4 items, 2 columns below 1024px and 4 from 1024px. All cards lazy (none `eager`). The current item is excluded and the 4 newest in-stock items of the same brand are shown.
- Hidden entirely (heading and link too) when the item has no brand, when the brand has no other in-stock item, or when this read fails (the row is a nice-to-have; the item page must not turn into the error screen because of it).

#### Loading, status and metadata

- **No `loading.tsx` for `/items/[code]` and none for `/brands/[slug]`.** Phase 2 recorded (decision 02-05) that once a `loading.tsx` streams a skeleton the response is already 200, and a later redirect becomes a meta refresh. The same applies to `notFound()`: with a streamed skeleton, a gone item or unknown brand would return 200 and fail success criterion 3. Both pages await their data before rendering anything, so `notFound()` produces a real 404. Cached reads keep this fast.
- Item page: `await connection()`, read `/items/{code}` through the tagged client, `notFound()` on the API's 404 (D-11). Unrelated API failures reach the existing `error.tsx`.
- Metadata (D-16): `generateMetadata` returns the title `{brand} {title}` (brand omitted when null) and a canonical from `SITE_URL`. Site-wide titles and Open Graph stay in Phase 4.
- JSON-LD (SEO-02, D-16): one `<script type="application/ld+json">` in the page, no visible UI. Contents: `@type: Product`, `name` (the title), `image` (array of the photos' `url`), `brand` as `{ @type: Brand, name }` when present, and `offers` as `{ @type: Offer, price` (cents / 100 with 2 decimals as a string), `priceCurrency` (the item's currency), `availability: https://schema.org/InStock`, `itemCondition: https://schema.org/UsedCondition`, `url` (canonical) `}`. The serialised JSON must escape `<` so item text cannot close the script tag. No `sku`, no internal ids, no cost.

### Gone-item page and generic 404 (ITEM-06, D-09, D-10)

- Both are real 404 responses (`notFound()` rendering `not-found.tsx`). Both set `noindex` (Next adds it for 404).
- Gone item (`src/app/items/[code]/not-found.tsx`): centred `StatusScreen`-style block (Heading title, Body message, one primary "Shop all items" button), then, 64px below, the "Newest drops" heading (Heading) and the 8 newest in-stock items in the normal grid (2 columns below 1024px, 4 from 1024px, 2 rows of 4, none eager). The newest items are read in the not-found component through the tagged client (`getItemsPage` with the default query and the page size set to 8). No item details are ever shown (the API drops sold items).
- Nothing says "sold out" with a badge or counter (out of scope: no sold badges, no urgency).
- Generic not found (`src/app/not-found.tsx`, also used for an unknown `/brands/[slug]`): a centred `StatusScreen` with the title, message, and two buttons (primary "Shop all items", secondary "Go home"). No drops grid.
- Because the existing `StatusScreen` renders its own `<main>`, the gone page needs the same block without nesting a second `<main>` (give `StatusScreen` a bare/`as` option or render a `div` variant). One `<h1>` per page.

### Brands page (`/brands`; BRAND-01, BRAND-03, D-12)

- Banner: the same Forest banner as All Items (`CatalogueBanner`, which now takes a `title`), Display title "Brands" on the left, solid Forest when `SHOP.bannerImage` is null.
- Below the banner (container, 48px padding-y on desktop, 24px on phones): the tile grid, ordered A to Z by brand name (case-insensitive, accent-insensitive compare), brands from `/filters`.
- **Tile.** The whole tile is one `<a href="/brands/{slug}">` (`prefetch={false}`). 3:2 aspect ratio, Ivory fill, 1px Stone border, hover fill Sand 40% (150ms; none under reduced motion), focus ring on the tile. Contents centred.
  - Logo tile: shown only when `public/brands/{slug}.svg` exists. A `next/image` with `fill`, `unoptimized`, `alt` = the brand name, `object-contain`, 24px padding, `loading="lazy"`, `mix-blend-multiply`. The tile frame is fixed by the aspect ratio so nothing shifts while logos load.
  - Text tile (no logo): the brand name in Bodoni 700 24px, centred, `line-clamp-2`, `break-words`.
  - No counts, no caption under a logo (the alt text carries the name).
- The set of logos that exist is read from the file system at build/run time on the server (as the existing slug rule requires); a missing file never throws.
- Empty (no brands in `/filters`): no tiles, `COPY.stock.empty` centred.

### Brand page (`/brands/[slug]`; BRAND-04, D-13, D-14)

- It is the full `/shop` catalogue with the brand locked. Same banner shape, toolbar, sort, search, chips, grid, pager, filter sidebar and drawer, URL handling, noindex,follow rules and canonical logic (canonical is `/brands/{slug}` plus the cleaned query).
- Banner: the same Forest banner, Display `<h1>` = the brand name (text, never the logo: logos are dark and would vanish on Forest). Above the title, a 16px `ArrowLeft` plus "All brands" back link (Label, Ivory, 44px hit area) to `/brands`.
- Locked brand: the Brand filter group is not rendered (sidebar and drawer), there is no Brand chip, and any `brand` param in the URL is ignored. Every other group still shows its values from `/filters`.
- Base path: every form action, chip link, pager link, sort and "Clear all filters" link targets `/brands/{slug}` instead of `/shop` (the Phase 2 components take a base path instead of the hard-coded `/shop`). A filter or sort change still resets to page 1 and `page` past the end still redirects to the last page.
- An unknown slug (not the slug of any brand in `/filters`) returns the generic 404.
- Header: Brands dropdown rows link to `/brands/{slug}` and "All brands" to `/brands` (D-15); the top-level "Brands" nav item is current (1px Forest underline) on `/brands` and every `/brands/...` page. No nav item is current on item pages.

### Motion and accessibility

- Inherited: 150 to 200ms `ease-out`, everything off under `prefers-reduced-motion: reduce`, 2px Forest focus ring at 4px offset, all text at least 4.5:1.
- Thumbnail click, lightbox arrows and track scrolling use smooth scrolling only when reduced motion is not set.
- One `<h1>` per page. The gallery, lightbox and tile grid are labelled as above. The brand tile grid is a `<ul>` of `<li>` links.
- External links: `target="_blank"`, `rel="noopener noreferrer"`, visually hidden "(opens in a new tab)".
- No horizontal scroll at 320px: the phone track is the only scroller and it scrolls inside its own frame; the details `<dl>` wraps long values; the tile grid is 2 columns. Test at 320px, 375px, 768px, 1024px and 1280px.
