## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions (main) -> Cloudflare API | The deploy token can change the production Worker |
| How many -> deployed webhook route | Real signed webhooks from the internet |
| Owner machine -> Worker secrets | The webhook secret moves from How many to Cloudflare by hand |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Elevation of privilege | CLOUDFLARE_API_TOKEN | high | mitigate | Token from the Edit Workers template plus D1 Edit and Workers R2 Storage Edit only, limited to this account and the cgaudino.com zone; used only by deploy-workers.yml on push to main, never in pull_request runs |
| T-01-17 | Information disclosure | HOWMANY_WEBHOOK_SECRET | high | mitigate | Set only with `wrangler secret put`; never in wrangler.jsonc vars, the repo or CI (deploy uses a labelled placeholder at build); the live proof reads it with `read -s` |
| T-01-18 | Spoofing | deployed webhook route | high | mitigate | Same HMAC verifier as CI; the deploy smoke asserts an unsigned POST gets 401 |
| T-01-19 | Repudiation | webhook outcomes | low | accept | Workers observability keeps the route's one-word warn logs (refused/ignored); no body or secret is logged |
| T-01-SC | Tampering | npm ci in deploy | high | mitigate | `npm ci` from the lockfile approved in Plan 01; tests run before the build in the deploy job |
