## Phase Goal

**As a** shopper, **I want to** browse, filter, search, sort and page through the shop's in-stock pieces in the Blacktail Archive look on desktop and phone, **so that** I can quickly find pieces in my size, brand and budget.

<objective>
Make the catalogue's state visible and controllable on /shop: the result count, removable chips for every choice (including a header search), a helpful empty state, the sort control and the SEO rules for filtered listings. After this plan a shopper who lands on a shared or searched URL sees what is applied, removes choices one at a time, sorts, and is never stuck on an empty page.

Purpose: CAT-09, CAT-05 and SEO-04, plus the shared pending state (CatalogueShell) that Plan 09's filter panel reuses.
Output: FilterChips, SortSelect, CatalogueShell + GridBusy, seo.ts, generateMetadata on /shop.
</objective>

## Intended interaction with SEO-03 (recorded decision, until Phase 4)

Filtered, searched and sorted /shop pages carry the page meta `noindex, follow` (SEO-04, this plan). The site-wide `X-Robots-Tag: noindex, nofollow` header in next.config.ts (the SEO-03 pre-launch guard from Phase 1, matching D-11's "noindex until Phase 4") stays, so crawlers see `nofollow` on the wire and obey the stricter value: the `follow` has no effect until Phase 4 makes the header depend on the environment. This is intended, not a bug, and this plan must not change it (prohibition above, T-02-17). Phase 2 proves the page-level value is right; Plan 10 pins the header value on a filtered /shop URL in CI and in the deploy smoke so the interaction stays observable, and lists it in the PR body.
