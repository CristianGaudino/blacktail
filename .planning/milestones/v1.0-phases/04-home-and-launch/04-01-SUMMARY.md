# Phase 4 Plan 01: SEO and indexing switch Summary

One fail-closed `ALLOW_INDEXING` flag now drives robots.txt, the robots meta and the X-Robots-Tag header, a dynamic sitemap reads through the tagged client, and every existing page has its own title, description, canonical and Open Graph tags.

## What was built

- `src/lib/indexing.ts` (no imports): `isIndexingOn` and `securityHeaders(indexingOn)`; next.config.ts imports it with a relative path. X-Robots-Tag is dropped only when the build env has `ALLOW_INDEXING=true`.
- `ALLOW_INDEXING` in the env schema (`'true' | 'false'`, optional, transformed to boolean). A typo or an empty string fails with `ALLOW_INDEXING: must be true or false`.
- Layout `generateMetadata` and `listingRobots(query, indexable)` follow the flag; filtered, searched, ranged and sorted listings stay `noindex, follow`.
- `robots.ts` and `sitemap.ts` call `await connection()` first, so the build makes zero How many calls and the flag is read at run time. Off: `Disallow: /`, no Sitemap line, empty sitemap. On: `Allow: /`, `Disallow: /api/`, absolute Sitemap line, 6 fixed pages plus every brand and in-stock item.
- `getItemsPage(search, limit = 24)`; the sitemap reads pages of `CATALOGUE.sitemapPageSize` (100).
- `pageMetadata` (title, description, canonical, full Open Graph block with the default or a given image); `SHOP.seo`, `COPY.seo`, `IMAGES.ogDefault`; item pages use the name, size, condition and cover photo with its dimensions.
- Shop-string guard now takes every SHOP string of 24+ characters as a needle.
- `public/images/og-default.jpg`: 1200x630, Forest with the logo in Ivory, 15 KB (generated by an uncommitted scratch script using the repo's sharp).
